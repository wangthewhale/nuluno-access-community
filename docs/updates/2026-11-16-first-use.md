# One task, one authorized read, one revocation that sticks

## English feature post

An agent restarting should not mean reconnecting an account, paying for the same task again, or silently getting a replacement key after you revoke access.

The new Nuluno Access public trial uses one command. It reads a real public Mastodon post through MCP, resumes the **same task through the SDK**, revokes its key, and starts a fresh service process to prove the old key is denied. The task's provider-call count remains one.

```sh
node scripts/try-first-use.mjs
```

The unchanged 0.1.0-alpha.2 core and helper passed the four phases on macOS/arm64 with actual exits `[0, 0, 0, 3]`. A repeated driver invocation displays its historical record and performs zero new provider actions.

[Run the real trial](https://github.com/wangthewhale/nuluno-access-community/blob/main/docs/one-command-trial.md) · [Inspect the receipt](https://github.com/wangthewhale/nuluno-access-community/blob/main/docs/evidence/one-command-first-use-20261116.json)

Tell your agent:

> Read https://raw.githubusercontent.com/wangthewhale/nuluno-access-community/main/docs/one-command-trial.md . Explain the local installation and public-read scope. With my setup authorization, run the trial from a reviewed checkout. Preserve any existing task/state. Show native revoked-key denial; do not replace the key or task. Do not connect private accounts or request broader scopes for this trial.

The Apache-2.0 community core and public-data trial are free. Private connector capabilities and their account/platform prerequisites are separate; this trial does not verify private mail or social posting. [Product details](https://access.nuluno.com/?lang=en).

## 繁體中文功能貼文

AI 換一個程序，不應該就叫你重新授權，也不應該把同一個工作重做；你撤銷鑰匙後，它更不應該偷偷換一把繼續操作。

Nuluno Access 這次的一指令試用，會透過 MCP 讀一則真的公開貼文，再透過 SDK 接回**同一個任務**。撤銷後，重新啟動服務，原鑰匙確實會被拒絕；provider 呼叫數保持 1。

未修改的 0.1.0-alpha.2 核心與原 helper，已在 macOS/arm64 跑通四個階段。再執行同一個指令只讀回既有記錄，不會新增一次 provider 動作。
